This repository's proof debt, in the four dispositions the trusted-base policy
allows. An escape hatch is either discharged, budgeted and tested, a necessary
axiom, or debt. There is no fifth category and no silent one.

The difference from most repositories' version of this file: everything below is
empty, and that emptiness is *enforced* rather than asserted. `scripts/check.sh`
refuses the build if any `.agda` file under `src/SecretTypes` or `tests`
contains `postulate`, and the same tree is compiled with `--safe`, which
independently refuses `postulate`, `{-# TERMINATING #-}`, `{-# NON_TERMINATING #-}`
and `--type-in-type`. `verification/receipts/agda-pwg_praxis.deed` records the
counts (`postulates = 0`, `escape-hatches = 0`) *derived from the tree*, and CI
fails if they move.

== (a) Discharged in this repo

_None — and none ever needed._ No escape hatch was ever introduced here to be
later discharged: the development has been `--safe` since its first module, so
there is no historical debt that a reader would otherwise have to trust a
changelog about.

Evidence: `scripts/check.sh` step 0 (trusted base), `scripts/proof-flags.sh`
(the `--safe` flag and why), and the `[trust-base]` block of the receipt.

== (b) Budgeted — tested with refutation budget

_None._ No escape hatch is covered by tests with a refutation budget, because
there is no escape hatch.

Not to be confused with, and deliberately not filed here: the two *negative
controls* (`tests/reject/{ExplicitFlow,ImplicitFlow,ThirdVariable}`) and the
leak witnesses (`SecretTypes.Witness`). Those are checks of the typing rules,
not escapes from them — a fixture that type-checked would be a failure, and
`scripts/check.sh` fails if one is accepted, or if it fails for the wrong reason
(missing import, parse error, unsolved meta). Calling them "budgeted debt" would
misreport what they are.

== (c) Necessary axiom

_None._ No axiom is assumed, so nothing needs a justification, a citation or a
trust-boundary entry.

This is the load-bearing sentence for the repository's status claims: with no
postulates and no axioms in the trusted base, `PROOF-STATUS.adoc` may use the
ledger token `proven` rather than `proven-with-postulates`
(`standards/docs/README-EXPLAINME-STANDARD.adoc` §5, `PROOF-POLICY.adoc` §5). If
an axiom is ever needed, the procedure is fixed in advance: name it here with its
justification, list it in that claim's trust-boundary column in the
link:EXPLAINME.adoc#proof-ledger[Proof Ledger], and demote the token in the same
change. `scripts/grade-receipt.sh` counts axioms, so the receipt cannot quietly
keep saying zero.

== (d) DEBT — actively to be closed

_None in the proof development._

Two items are open *obligations* rather than proof debt, and are listed here so
that they are not mistaken for either:

* *Recheck legs (`PWG-2ii`, met 2026-11-09).* `PROOF-POLICY.adoc` §2 asks for
  every Agda theory proof to be rechecked in Rocq and in Lean. Both legs now
  exist, re-proved by hand without a library or an axiom
  (link:../verification/legs/README.adoc[`verification/legs/README.adoc`]),
  and the receipt records them. The obligation that remains is review: the
  statement comparison was written by Claude Code and is provisional until the
  owner reviews it. `PWG-1` (a per-commit receipt of each checker's observed
  result) is not met.
* *Termination-sensitive noninterference.*
  `Noninterference.OutcomeVisibility.termination-sensitive-fails` refutes TSNI
  for the current typing rules when finishing versus non-finishing is public.
  Designing and proving a stronger discipline, or specifying a different
  observer, remains an open research obligation rather than proof debt.

== Who checks this file

* `scripts/grade-receipt.sh --check` (CI: `.github/workflows/proofs.yml`) — the
  derived counts, and the claim IDs, must match the tree and
  `PROOF-STATUS.adoc`.
* `scripts/check.sh` — `postulate` refusal, then the full gate.
* The receipt's `[trust-base]` block is the machine copy of sections (a)–(c).

A future addition to this file that is not accompanied by a change in those three
places is a claim the gate does not support.

[[waivers]]
== Waivers — obligations this repository does not meet

None is open. W-1 is kept below, closed, as the record of how the obligation
came to be met.

A waiver is not an escape hatch inside a proof and not proof debt. It is an
obligation the *policy* sets that this repository does not yet satisfy, recorded
in the place a reader will look. Each one names the obligation, the tool, and why
the mapped option was not used (`PROOF-POLICY.adoc` §4 asks for exactly that
shape when a mapped prover is not the right fit).

=== W-1 `--cubical-compatible` (PROOF-POLICY §2.1, dated 2026-11-01) — CLOSED 2026-11-09

*Obligation.* `agda --safe --without-K --cubical-compatible <module>` is the
canonical invocation for first-party Agda theory entrypoints.

*State.* **Met.** `scripts/proof-flags.sh` carries `--cubical-compatible` beside
`--safe --without-K --no-libraries --ignore-interfaces --double-check -W error`,
and `scripts/check.sh` and `scripts/minimal-laws.sh` pass under it: core proofs,
all four expected rejections at their intended declarations, and the
laws certificate. With `-W error`, any `-WUnsupportedIndexedMatch` fails the
gate, so the flag cannot be nominally on while the check is off.

*History.* Three CI runs on 2026-11-01 adopted the flag and then reported why it
would not stay (Agda `2.6.4.3`, `agda-bin=2.6.4.3-1+b2`):

. `Prelude.agda:43` `just-inj`: injectivity of `just`. Fixed then: dead code,
  deleted.
. `Prelude.agda:91` `_≟_`: injectivity of `suc`. Fixed then: `suc-dec` pulls
  the answer back along `pred`, which computes definitionally.
. `Lattice.agda:46` `⊑-trans`: every clause matching the two-point order was an
  indexed match on `_⊑_`. Fixed then (arm B1): `_⊑_` became a computed
  predicate (`L ⊑ _ = ⊤`, `H ⊑ H = ⊤`, `H ⊑ L = ⊥`). Its one cost is that a
  witness such as `L⊑H` no longer pins its target label by its type, so
  `Countermodels.NoDownClosure` names its indices (`h {x = L} {y = H}`).

That left 13 warnings, all `injectivity of the data constructor just`, in `tini`,
`go`, `confine` and `confineW`. They came from matching an equation
`exec fuel c s ≡ just t` against `refl`. This record used to say that only a
relational big-step semantics would remove them (arm B2), and that this would
restate N-5 and reshape N-1/N-7, an owner decision about the theorem.

*How it closed (2026-11-09).* That was not necessary. The proofs no longer match
such an equation. `SecretTypes.Prelude` defines `from-just` and
`just-injective e = cong (from-just a) e`, a retraction: both sides of
`cong (from-just a) e` reduce to the two values, so no injectivity rule is used.
This is the same technique `suc-dec` already uses with `pred`. In
`Noninterference.Generic` the six affected clauses go through one helper,
`≈-just : just s ≡ just t → just s′ ≡ just t′ → s ≈ s′ → t ≈ t′`, built from
`just-injective` and `subst`. The semantics, N-5 and every theorem statement are
unchanged, and the receipt's module hashes record the two changed modules.

*What would make this record wrong.* If `-WUnsupportedIndexedMatch` were
suppressed in the gate, the flag would be nominally on and the check off. The
gate does not suppress it, and `scripts/proof-flags.sh` is the single place the
flags live.

*Consequence for the grade.* Before this closed, the proved rows were
`ungraded` under `PROOF-POLICY` §8.2, which makes `PWG-3` conditional on the §2.1
invocation; this file said "Grade 3" at the time. They are now `PWG-3`. The
receipt records `cubical-compatible = "met"`.
