== The audit

=== 1. Central substrate — VeriSimDB as the only shared channel

*Understanding.* `ECHIDNA`, `echidnabot` and `proof-burrower` speak to each
other only through VeriSimDB via VCL; no system-to-system protocol exists
between them. VeriSimDB's modality *profile* is the Octad — eight fixed slots,
while any one subject's modality *set* may be a strict subset.

*STATUS:* ✅ Consistent (with one stale payload-shape finding, F-3).

*ONE-LINE EVIDENCE:* `grep -ri` over the tree finds **zero** occurrences of
`echidna`, `proof-burrower` or `VCL`; the only VeriSimDB surface is the optional
template feed `.machine_readable/integrations/verisimdb.a2ml` and the
`kind = 'verisimdb` evidence sinks in the six contractiles — i.e. one hub, no
new point-to-point channel.

*ACTION:* none for routing. Correct F-3 (`format = "hexad"`) with the VeriSimDB
shape, not with a guess.

=== 2. Echo → Resource directionality

*Understanding.* `EchoBridge` proves the bridge runs E→R only and
`NotResourceInstance` proves Echo is not a resource instance; conversion is
one-directional and cannot be run backwards.

*STATUS:* ✅ Consistent.

*ONE-LINE EVIDENCE:* no conversion, coercion, marshalling or `instance` code
exists in the tree; Echo appears only as prose — the `echo-types` neighbour row
(`docs/secret-types.adoc`), the two-run/one-run separation argument
(`PROOF-STATUS.adoc` "Separation from siblings"), and the estate map's
`Secret → (none yet) | OPEN` row.

*ACTION:* none. Boundary to keep: the README's Echo *conjecture* must stay
worded as "the public observer's Echo fibre does not separate secret inputs" (a
property of a reading) and must never be restated as an Echo↔Resource
conversion.

=== 3. No universal adapter

*Understanding.* `hub_ceiling` proves universal interoperability impossible, so
backend-specific adapters are mandatory; any single unified adapter is a
category error.

*STATUS:* ✅ Consistent.

*ONE-LINE EVIDENCE:* the only `adapter` strings in the tree are
`zig-unified-api-adapter` in inherited template files
(`.machine_readable/descriptiles/PLAYBOOK.a2ml:84`,
`.machine_readable/integrations/groove.a2ml:4`) plus the CC licence text —

*ACTION:* none.

=== 4. `absolute-zero` status

*Understanding.* `absolute-zero` supplies CNO/OND, has 115 `Qed` against 61
undischarged axioms, consumes proof infrastructure rather than providing ground
truth, and leaves OND-6 open by design.

*STATUS:* ✅ Consistent.

*ONE-LINE EVIDENCE:* **zero** occurrences of `absolute-zero` anywhere in the
tree; this repository depends on nothing from it and re-states none of its
obligations.

*ACTION:* none now. Standing rule for later: if declassification work ever
consults CNO, cite it as a consumer with 61 open obligations and never as
axiom-free truth. This repository's baseline declassifies nothing, which is
compatible with OND-6 being open by design.

*STATUS:* ✅ Consistent here; ⚠️ *hazard flagged in the estate map, which is not

== Summary

The structural understanding is **intact and, in the places that matter, better
than intact**: this repository is one of the few that recorded the RMO
name-inference correction instead of absorbing it. Nothing in active work has
drifted from the proven invariants.

What *has* drifted is the paper layer around the proofs — and it drifts in the
characteristic direction: a manifest that says `gated` for a tree no workflow
checks, a `CLADE.a2ml` that names another repository, a family-map row claimed
as "proposed" after it landed, a VeriSimDB feed shaped for six modalities after
the engine became an octad, and a report format naming a removed tool. These
are F-1, F-2, F-3, F-4, F-5. None of them is a proof error; all of them are the
"name instead of code" error at document level, which is the failure mode the
estate has already been burned by.

The estate-level items to send elsewhere are in
link:estate-handoff-prompts-2026-11-01.adoc[estate-handoff-prompts-2026-11-01].

=== Honest edges of this pass

* **The flags changed without a local run.** No Agda exists in this sandbox, so
  `--cubical-compatible` was adopted from the policy and verified in CI, not
  before it. If CI rejects it, the flag and the receipt are reverted and F-11
  reopens as a blocked item — the policy's own rule is that flags are never
  weakened to make a check green, so a failure is reported, not absorbed.
* **The receipt is not a proof.** It records which gate produced which result and
  at which commit; the CI log remains the execution evidence.
* **Mathesis grades theorems, not checks.** N-4/N-5/N-6 are recorded
  `below-grade-3` with the token `tested-only` rather than graded, because a
  refusal fixture and a shell-orchestrated ablation certificate are not theorems.
