= Sandbox toolchains and version pins
:revdate: 2026-11-01
:toc:
:icons: font

What this session could install, what it could not, and the exact versions the
estate's provers are at — so that "latest stable" is a recorded fact rather than
an assumption. Provisioning is scripted in `scripts/dev-toolchain.sh`; nothing
below is hand-installed magic that a later session cannot repeat.

== Installed and verified

[cols="1,2,3",options="header"]
|===
| Tool | How | Verified by

| *Agda 2.7.0.1* (`2.7.0.1-cf6e2d9`)
| `pip install agda` (a Python binding to Agda's Haskell library) **plus** the
  data directory from `npm install agda-wasm`, symlinked into the binding
| `SecretTypes.All` typechecks; `scripts/check.sh` green (core proofs + all three
  expected rejections); `scripts/minimal-laws.sh` green. Whole development in
  ~1.3 s, so the edit–check loop is usable.

| *Zig 0.17.0*
| `pip install ziglang`
| `python -m ziglang version`

| *Asciidoctor.js 2.2.9* (Asciidoctor 2.0.23 core)
| `npm install @asciidoctor/core@2.2.9 @asciidoctor/cli@3.5.0`
| `scripts/check-adoc-renders.sh` green over all 168 tracked `.adoc`
|===

The third row is the one that earned its place by failing first, and it is worth
the paragraph. CI installs the Ruby gem `asciidoctor` 2.0.26; this sandbox
cannot reach `rubygems.org`, so the first attempt used `@asciidoctor/core@4.1.1`,
the newest available. That build rendered **all 168 files clean** — and CI then
failed the very same gate on
`dropping cells from incomplete row detected end of table` in
`docs/reports/status/toolchain-and-version-pins-2026-11-01.adoc`: a table where
one row carried three cells into a four-column layout. Asciidoctor 2.0.x calls
that an error; 3.x core silently pads the row.

So the rule this repository now applies to its own instruments: **a render check
is only a check if its parser is the parser the gate uses.** The fix was to pin
the sandbox parser to the core version the CI parser tracks (2.2.9 is Asciidoctor
2.0.23, one patch line from 2.0.26), after which the local run reproduces CI
exactly. `scripts/dev-toolchain.sh docs` installs that one, and says why.

The Agda arrangement is ugly and worth stating plainly: the binding is not
usable without the data directory, and the wheel does not ship it, while the
npm package ships the data directory for both 2.6.4.3 and 2.7.0.1. "Agda
installed" and "Agda usable" are different claims; only the second is recorded
here.

== Not provisionable, with the blocker named

These are measured, not assumed (`scripts/dev-toolchain.sh status` repeats it):

[cols="1,2,3",options="header"]
|===
| Tool | Route that fails | Blocked host

| *Rust* / *Creusot* | `apt` (Debian `rustc`), `rustup-init` | `deb.debian.org`,
  `static.rust-lang.org`. GitHub release assets are also used by some
  distributions, and those redirect to `release-assets.githubusercontent.com`,
  which is blocked too.

| *Rocq / Coq 9.3.0* | `apt install coq`; the `coq/coq` release is **source
  only** (`rocq-9.3.0.tar.gz`) so it would need a full OCaml build
| `deb.debian.org` (OCaml not present either)

| *Lean 4.35.0* | `lean-4.35.0-linux.tar.zst` from the release assets | `release-assets.githubusercontent.com`

| *Idris2 0.8.0* | needs Chez Scheme and a self-host bootstrap | `deb.debian.org`,
  release assets

| *Lambdapi 3.0.0* (the `transported` route in PROOF-POLICY §2) | needs opam + OCaml
| `opam.ocaml.org` (not in the allowlist)
|===

Consequence, stated as a policy consequence rather than an excuse: **the Grade-2
legs cannot be produced in this sandbox**, and a leg that cannot run must not be
reported as passing (`PROOF-POLICY` §6 says exactly this). Anything Coq- or
Lean-shaped written here would be unverified text, so none was written; see
`PROOF-STATUS.adoc` and `verification/receipts/agda-grade3.a2ml`, which record
both legs as `unavailable`.

== Version pins, resolved on 2026-11-01

Queried from the projects' own release feeds. "Latest stable" is recorded for
the record, **not adopted blindly**: a pin is a reproducibility control, and
moving one changes every receipt below it.

[cols="2,1,2,3",options="header"]
|===
| Component | Latest stable | This repo's pin | Note

| Agda | `v2.8.0.2` (2026-09-13) | `2.6.4.3` (Debian `agda-bin=2.6.4.3-1+b2`) in
  CI; `2.7.0.1` locally
| Three different versions, deliberately: the CI pin is the reproducibility
  anchor, the local one is whatever the sandbox can get, and upstream is
  recorded. The development typechecks on both 2.6.4.3 (CI) and 2.7.0.1
  (local); 2.8.0.2 is untested here, so it is **not** claimed.

| Lean | `v4.35.0` (2026-10-12) | none | leg `unavailable`
| Rocq | `V9.3.0` (2026-09-19) | none | leg `unavailable`
| Creusot | `v0.14.0` (2026-10-12) | none | not applicable: no first-party Rust here
| Rust | `1.99.1` (2026-10-16) | none | not provisionable in this sandbox
| Idris2 | `v0.8.0` (2025-10-31) | template `src/interface/Abi/*.idr` only | ungated; no proof leg
| Lambdapi | `3.0.0` (2025-07-16) | none | the `transported` route is not attempted
| F* | `v2026.10.25` | none | a §4 exception tool; nothing here needs it
| Zig | `0.15.1` (GitHub) / `0.17.0` (PyPI wheel) | template `src/interface/ffi` only | two upstream channels disagree, so "latest" is ambiguous for Zig; the wheel is what a sandbox gets
|===

Recommendation, labelled: the *elegant* arm is one Agda pin everywhere
(2.6.4.3) plus a recorded note that upstream is 2.8.0.2; the arm actually in use
is CI pinned and sandbox floating, which is defensible only because the sandbox
never produces a receipt (CI does). If the sandbox is ever allowed to produce a
receipt, the two pins must be reconciled first.
